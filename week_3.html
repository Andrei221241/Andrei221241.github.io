Week 3: Application Selection for Performance Testing

Objective and planning for performance testing

Objective

In Week 3, I selected applications to evaluate the Ubuntu Server’s performance under different workloads. The goal is to prepare for detailed performance testing in Week 6 by choosing representative CPU-, RAM-, I/O-, and network-intensive applications. All selections are documented for justification; installation and testing come later.

1. Application Selection Matrix

Application / Service Workload Type Reason for Selection Expected Resource Use
Stress-ng CPU-intensive Generates high CPU load for testing system processing limits. High CPU usage, low RAM impact.
Memtester RAM-intensive Tests memory stability and allocation under heavy load. High RAM usage, minimal CPU impact.
Fio (Flexible I/O tester) Disk I/O-intensive Simulates read/write operations to measure disk performance. High disk read/write activity.
Iperf3 Network-intensive Measures network throughput and latency between server and workstation. Moderate CPU, high network utilization.
NGINX Server application Common web server to simulate real-world service load. CPU and RAM usage vary with simulated requests; network usage moderate.

Explanation: Applications were chosen to cover all major system resources and ensure that performance testing is comprehensive. Each tool is open-source, widely documented, and compatible with Ubuntu Server 22.04 LTS.

2. Installation Documentation (Planned Commands)

Although installation will occur later via SSH, the commands are documented here for clarity:

# CPU-intensive
sudo apt update
sudo apt install stress-ng -y

# RAM-intensive
sudo apt install memtester -y

# Disk I/O-intensive
sudo apt install fio -y

# Network-intensive
sudo apt install iperf3 -y

# Server application
sudo apt install nginx -y

Note: All installations will be performed on the Ubuntu Server via SSH from the workstation VM in later weeks.

4. Monitoring Strategy

To evaluate the server’s performance, I will use remote monitoring via SSH from the workstation once applications are running. The planned tools and metrics are:

  • CPU Usage: top, htop, or mpstat
  • Memory Usage: free -h, vmstat
  • Disk I/O: iostat, fio results
  • Network Performance: iperf3, ping
  • System Latency / Responsiveness: Observe delays under simulated workloads

Explanation: Monitoring will be systematic, with results recorded at baseline, during load, and post-load to identify bottlenecks and validate system stability.

5. Reflection

Selecting applications in Week 3 allowed me to plan for comprehensive performance testing in a structured and methodical way. By including CPU-, memory-, disk-, network-, and server-based workloads, I can ensure that all critical system resources are properly evaluated under different types of stress.
