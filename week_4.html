Week 4: Initial System Configuration & Security Implementation

Hardening the Ubuntu Server with SSH key-based authentication, firewall configuration, and secure user management, all performed via remote administration from the workstation.

1. Objective

The goal for Week 4 was to move from a basic Ubuntu Server installation to a securely administered system. Building on the provisioning work from Week 1 and the security planning in Week 2, I implemented practical controls: SSH key-based authentication, a host-based firewall, and non-root administrative accounts. All changes were made via SSH from the Ubuntu Desktop workstation to reinforce remote management skills.

2. SSH Configuration with Key-Based Authentication

Key pair generation

On the workstation VM, I generated a 4096-bit RSA key pair to use for secure access to the server: 

ssh-keygen -t rsa -b 4096 -C "andreimac@workstation"

This produced a private key (kept on the workstation) and a matching public key that can be safely copied to the server.

Authorising the key on the server

The public key was then copied to the Ubuntu Server so that SSH could trust the workstation: 

ssh-copy-id andreimac@192.168.56.102

This appended the workstation’s public key to ~/.ssh/authorized_keys on the server for the andreimac account.

Verifying passwordless login

Finally, I confirmed that key-based authentication was working: 

ssh andreimac@192.168.56.102

SSH connected successfully without prompting for a password, confirming that the key pair is being used and that interactive password authentication is no longer required for this user.

3. Firewall Configuration

To reduce the attack surface of the server, I configured UFW (Uncomplicated Firewall) to allow only SSH from the workstation’s IP address.

Installing and enabling UFW

sudo apt install ufw -y
sudo ufw enable

Restricting SSH to the workstation

SSH access was restricted to the host-only IP of the workstation: 

sudo ufw allow from 192.168.56.10 to any port 22

The resulting configuration, confirmed using sudo ufw status, allows incoming SSH only from the workstation and denies all other unsolicited connections by default.

4. User Management and Privilege Implementation

Administrative work should not be performed directly as root. To follow best practice, I created a dedicated non-root administrative user and granted it sudo capabilities.

Creating an administrative account

sudo adduser adminuser

Granting sudo access

sudo usermod -aG sudo adminuser

The combination of these commands created the adminuser account and added it to the sudo group, allowing privileged commands via sudo <command> while still requiring authentication.

Account creation was verified with: 

cat /etc/passwd | grep adminuser

5. SSH Configuration Hardening

With key-based access and a sudo-enabled user in place, I hardened the SSH configuration to remove unnecessary authentication methods.

Editing /etc/ssh/sshd_config

Before editing, SSH allowed root login and password authentication: 

PermitRootLogin yes
PasswordAuthentication yes

Using a text editor, I updated the configuration: 

sudo nano /etc/ssh/sshd_config

The relevant directives were changed to:

PermitRootLogin no
PasswordAuthentication no

Finally, I restarted the SSH daemon so the new settings took effect: 

sudo systemctl restart ssh

Disabling root and password authentication ensures that only authorised users with valid SSH keys can access the server.

6. SSH Access Evidence

To confirm that administration now flows through the hardened path, I logged in as the new administrative user using key-based authentication: 

ssh adminuser@192.168.56.102

The shell prompt changed to adminuser@ubuntu-server:~$, confirming that:

  • The adminuser account exists and is active.
  • SSH key-based authentication works for this account.
  • Administration can proceed without using the root account directly.

7. Remote Administration Evidence

All administrative commands are executed remotely from the workstation over SSH. Example commands include: 

uname -a

Shows the server kernel version, architecture, and hostname.

free -h

Displays memory utilisation in human-readable units.

df -h

Reports disk usage and available space on mounted filesystems.

ip addr

Lists network interfaces and their assigned IP addresses on the server.

Screenshots captured with the adminuser@ubuntu-server:~$ prompt illustrate that these commands are run from the workstation via SSH rather than from the server console.

8. Reflection

Week 4 was about turning plans into enforceable controls. Enabling SSH key-based authentication and restricting SSH to the workstation significantly reduced the server’s exposure to unauthorised access. Moving administration to a non-root sudo user follows the principle of least privilege and lowers the risk of accidental or malicious system damage.

Working exclusively over SSH strengthened my confidence in managing a headless Ubuntu Server. Comparing the SSH configuration before and after hardening made it clear how a few targeted changes—disabling root login and password authentication—can greatly improve system security. These measures now form a solid base for the deeper security verification and monitoring work planned for subsequent weeks.
